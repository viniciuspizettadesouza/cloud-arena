# Competitive Context

Cloud Arena occupies the greenfield architecture-decision space rather than general FinOps.

| Product category/example | Primary starting point | Difference from Cloud Arena |
| --- | --- | --- |
| CloudZero, Finout, Cloudability, CloudHealth, Harness | Existing cloud estate and billing | Cloud Arena starts before infrastructure exists. |
| Infracost | Architecture already expressed as IaC | Cloud Arena derives candidates from workload requirements. |
| Holori | Cross-provider service and price comparison | Cloud Arena adds generation, constraints, scoring, and explanation. |
| Pinpole | Early AI architecture/simulation exploration | Cloud Arena’s MVP is deterministic and has no LLM dependency. |
| IBM Txture | Existing estate and brownfield migration | Cloud Arena is explicitly greenfield-first. |

This is directional product research from the foundational brief, not a permanent feature audit. Revalidate competitor capabilities before using these claims in public marketing.

The differentiator is the complete chain from requirements to comparable target architectures, provider pricing, explicit constraints, ranked alternatives, and explainable assumptions—without accounts, telemetry, billing data, CMDB, Terraform, or Kubernetes.
